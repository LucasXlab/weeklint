# 验收审查与修复

三个独立子代理分别从正确性、安全/数据、新用户角度审查。每条先复现，再修；下面按严重程度记录结论。未修改项目文件的审查副本在 `/tmp/wlrev`，项目内没有保留。

## 已复现并修复

### 1. 长期 RRULE 在到达本周前就被 1000 次上限截断（严重）

- 复现：`DTSTART 2023-01-02`、`RRULE:FREQ=DAILY`，查 2026-W45；修复前 `events=0`、`busyMinutes=0`，并误报 `recurrence_truncated`。
- 原因：`_occurrences` 用 `islice(rule, 1001)` 从 DTSTART 数，先到 1000 就停，根本没走到本周。
- 修复：用 `rule.xafter(horizon_start - duration, ...)` 跳到与本周可能相交的实例，只对本周内实例计数；仍保留 1000 上限和 warning。
- 回归：`tests/test_ics.py::test_long_running_recurrence_starts_at_week`、`test_recurrence_truncated`。

### 2. 小于 min_block 的任务被放进碎片空档（中）

- 复现：周一工作时间只有 09:00–09:20，`min_block_minutes=30`，任务 20m；修复前仍排 09:00–09:20，`usableMinutes=0` 却 `scheduledMinutes=20`，同时 `overcommitted`。
- 原因：planner 的候选槽只看 `可用分钟 >= 任务分钟`，没有要求自由区间本身 ≥ min_block。
- 修复：`_find_slot` 要求 `max(chunk, min_block)`；任务本身小于 min_block 时允许小块，但必须放在至少 min_block 长的自由区间。
- 回归：`tests/test_planner.py::test_small_task_cannot_use_sub_min_block_slot`。

### 3. DST 日容量与块分钟数用墙钟而不是实际经过分钟（中）

- 复现：2026-03-08 周日 01:00–04:00，修复前 `workMinutes=180`，但实际只有 120 分钟；150 分钟块被写出，JSON `minutes=150`，ICS 实际跨度 90 分钟。
- 原因：`minutes_between` 用 `(end - start)`，同 tzinfo 的 aware datetime 相减是墙钟；`start + timedelta` 也是墙钟。
- 修复：`minutes_between` 先转 UTC；新增 `add_minutes` 按实际分钟加，planner 放块和 buffer 扩展都用它。容量、块分钟、ICS 跨度一致。
- 回归：`tests/test_planner.py::test_spring_forward_capacity_is_elapsed_minutes`、`test_spring_forward_block_minutes_are_elapsed`。

### 4. 未闭合元数据被当标题，截止日期和估算静默丢失（中）

- 复现：`- [ ] 坏任务 @estimate(30m`；修复前标题含 `@estimate(30m`，估算变默认 60m；`@due(2026-11-05` 同样丢截止。
- 修复：标题里残留 `@key(` 直接 `task_parse_error`，给行号和截断片段，不再静默。
- 回归：`tests/test_tasks.py::test_unclosed_metadata_is_an_error`。

### 5. Rich markup / ANSI 让人类输出崩溃或注入终端（中）

- 复现：标题 `[/]` 使 `weeklint check` 抛 `MarkupError`，退出 3；标题含 ESC OSC 会原样写进终端。
- 修复：人类输出统一 `_user()`：去掉控制字符并 `rich.markup.escape`；表格、findings、today、explain 都走它。
- 回归：`tests/test_cli.py::test_human_output_escapes_rich_markup`。

### 6. 错误消息回显巨大用户值（中）

- 复现：1 MiB 的 `@estimate(...)` 错误 stderr 约 2 MB；40 KB ICS summary 被完整回显。
- 修复：`_short()` 截断到 40/60 字符，detail 也存截断值；ICS 解析异常截到 200 字符。
- 回归：现有错误用例；新增长值路径由 `test_tasks.py` 的 estimate 用例覆盖。

### 7. 其他可靠性问题

- 深层 YAML `RecursionError` → 现在 `config_invalid_yaml`，退出 2。
- `--week 9999-W52` / `--now 9999-12-31` 的日期溢出 → `invalid_week` / `invalid_now`，不再退出 3。
- ICS 展开事件上限改为边展开边检查；结束时间溢出改为 `ics_invalid_event`。
- `plan.prev.json` 改为原子写；输出路径与输入文件同名时 `config_invalid_path`，不覆盖输入。
- 锁释放只删除自己的 PID；陈旧锁被别的进程接管后不会误删。
- `init` 读到的 `TZ` 先用 `ZoneInfo` 验证，避免把非法值/换行写进 YAML。

## 新用户审查的修复

- `plan` 按当前 ISO 周排整周，周中运行会包含过去时段：README 改成「周一早上」；周日排下一周用 `--week`；`today` 标出「已结束/进行中」。这是 SPEC 幂等要求下的有意取舍，记录在 `docs/deviations.md` D16。
- 快速开始固定 2026-W45：加说明「其他日期加 `--now`/`--week`」，不再把固定日期当成任何一天都会得到的结果。
- 报告空状态不再说「这周装得下」，而是「还没有任务」；超载时进度条按 `max(已排, 需求)/容量` 画，需求 20h 容量 1h 也能看到满条。
- 打印强制浅色 token，不再从深色模式打印出黑底。
- `--help` 增加全局参数 epilog；`check --help` 也能看到。
- `.weeklint` 是隐藏目录，README 改为 `open .weeklint/report.html` / `Cmd+Shift+G`，不再说「双击」。
- 人类模式错误格式写清楚：消息 + 错误码 + detail JSON；`--json` 才是单个 envelope。
- `plan.md` 改为 SPEC 要求的按天表格；页脚补上「由 Weeklint 在本地生成；没有上传任何数据」。
- 未排程原因在 plan/report 里显示中文标签，不再直接写 `no_capacity`。

## 未修复/已知

- `plan` 周中仍按整周排，已过去的块会留在 JSON/ICS；这是幂等契约下的取舍，README 和 D16 已写明。`today` 会标状态。
- 非法 DTSTART/DTEND/RRULE 被 `icalendar` 库静默丢弃时，只能给 missing-start/missing-end 或按单次事件处理；库层无法恢复原始属性。已在限制里说明。
- FIFO/设备文件没有专门拦截；`stat` 大小检查后读取可能阻塞。普通本地使用不涉及，作为后续加固项。
- Windows 仍未实机验证。

## 误报/不成立

- 「13 个文件未提交，fresh clone 不是当前工作树」：审查时快照早于后续提交，现在已提交；不是产品缺陷。
- 「某些 RRULE 直接退出 0」：`icalendar` 对非法 RRULE 属性直接丢弃，未进入我们的异常分支；属库行为，已归入限制。
- 「250m 应为 85+85+80」：SPEC §6.4 的 floor 公式是 84+83+83；§11.5 示例已改成 84+83+83，测试与实现一致。
