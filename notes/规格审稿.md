# 规格审稿记录

审稿方式：独立子代理只读 `SPEC.md` 和 `DESIGN.md`，不读代码、不改文件。要求逐条检查歧义、矛盾、漏写的错误、不可测试规则、缺数字、设计与规格冲突、安全/数据损失。

## 必须修的 8 条与处理

1. **日历缺失/为空/不可读三态混淆**：已在 2.2 明确「空数组 → `no_calendar_files` 退出 0；文件缺失 → `calendar_file_not_found` 退出 2；不可读 → `calendar_file_unreadable` 退出 2」，并删掉 4.2 的模糊表述。
2. **`atRisk` 没定义**：5.1 改为 `overcommitted && due != null && due <= week.end`；plan 同名字段按 6.4 覆盖；7.1 引用具体条款。
3. **plan 退出 1 缺 finding**：新增 `task_unscheduled`（error），plan 退出条件统一为「至少一个 error finding」；DESIGN 的「这周装得下」改为「无 error 且 `tasksUnscheduled==0`」。
4. **显式 `@id` 无字符集**：3.1 规定 `[A-Za-z0-9_-]{1,64}`，越界 `task_invalid_id`；ICS UID/DESCRIPTION 只使用合法 id，避免注入。
5. **切块 5 分钟取整与总和矛盾**：取消 5 分钟倍数要求，改为 `floor` 分配、前 `total % n` 块各多 1 分钟，总和严格等于 total；121 分钟示例改为 61+60。
6. **`2026-W53` 被当成非法周**：改用 `2027-W53` 作非法示例，并补 `2026-W53 = 2026-12-28…2027-01-03` 的合法用例。
7. **幂等条款与 locked 冲突**：幂等比较排除 `generatedAt`、`now`、`blocks[].locked`；锁定块 `reason` 固定为 `scheduled`，保证其余字段一致。
8. **demand 范围不一致**：`taskCount`、`estimatedMinutes`、`unestimatedCount` 全部限定为 5.2 范围内任务；截止晚于本周的任务只发 info，不计入需求。

## 其余已处理的审稿意见

- `fragmented_day` 改为「存在 <min_block 的自由区间且当天没有任何 ≥min_block 的区间」，否则永不触发。
- 容量示例 `freeMinutes` 改为 1680（2400−720）。
- `PlanOutput` 增加 `days[]`，DESIGN 的每日「可用」固定用 `usableMinutes`。
- DESIGN 指标口径固定：可支配=`usableMinutes`、任务需要=`estimatedMinutes`、缺口=`gapMinutes`；容量条宽度用 `scheduled/capacity`；`capacity=0` 有专门文案。
- 新增 `--text-metric-sm`（28px）和 `--text-print`（11pt）；DESIGN 2.5 给出测试必须断言的 token 清单。
- `write_failed` 覆盖「临时文件写入或 `os.replace` 失败」，并规定清理临时文件、已完成替换的文件保留。
- DST：不存在时间顺延、歧义时间 `fold=0`，新增 `dst_adjusted` warning。
- 并发：`plan` 用 `.lock`（O_EXCL），陈旧锁 10 分钟；`init` 用 O_EXCL 并回滚本次已创建文件。
- ICS 上限：单文件 5000 VEVENT、本周 20000 实例、单事件 1000 实例截断；无限 RRULE 在本周结束后停止。
- UID fallback 含来源文件+序号；去重要求 UID+start+end 全同，并 warning `duplicate_event`。
- doctor 的输入错误走错误 JSON 退出 2，findings 只放 warning/info；新增 `output_dir_unverified` warning。
- `deadline_at_risk` 的 check 固定文案与 plan 必含字段分开写，消除冲突。
- `plan.ics` 改用 UTC 时间 + 75 octet 折行，避免无 VTIMEZONE 的 TZID 导入问题。
- init 文案改为 3 行注释（第 2 行是注释掉的示例任务）。
- 补 `version` 子命令；`today/init/doctor/version` 带 `--week` 报 `invalid_argument`；argparse 错误转 JSON。
- DESIGN 摘要统一为「两列 + 第三项跨列」；未排程空状态按「无任务 / 全排下」分支；只有 info 时标题「提醒（N）」并展示。
- 新增 `previous_plan_ignored` finding，覆盖旧 plan 无法解析/版本不符/周不符。
