# 真实使用记录

日期：2026-10-29。环境：macOS 15 / Python 3.13.5 / Weeklint 0.1.0 editable install。所有命令用 `--now` 固定时间，避免「今天」变化导致输出不可复现；临时目录在 `/tmp/wl-runs`。

覆盖正常流程 + 9 个异常/边界场景。退出码用 `echo $?` 记录。

## 1. 正常一周（示例输入）

```bash
weeklint check --config /tmp/wl-runs/normal/weeklint.yaml --now 2026-11-02T08:30:00-05:00
weeklint plan  --config /tmp/wl-runs/normal/weeklint.yaml --now 2026-11-02T08:30:00-05:00
```

- 结果：check 退出 0；plan 退出 0。
- 容量 24h30m，需求 11h45m，缺口 0；8 个块；写出 4 个文件。
- 输出与 `assets/screenshot-desktop.png` 一致。

## 2. 超额承诺

两个任务共 3000 分钟，本周可用 1470 分钟。

- check 退出 1，`overcommitted` + 两条 `deadline_at_risk`。
- plan 退出 1，仍写出计划；`task_unscheduled` 记录剩余分钟，未排程任务整条回滚。

## 3. 非法估算

`@estimate(0m)`：

- 退出 2，`task_invalid_estimate`，`detail.line=1`，提示 5–2400 分钟。

## 4. 非法 ISO 周

`--week 2027-W53`：

- 退出 2，`invalid_week`，提示 `YYYY-Www`。
- 另测 `2026-W1`（未补零）同样退出 2；`2026-W53` 合法。

## 5. 日历文件缺失

`calendar_files: [missing.ics]`：

- 退出 2，`calendar_file_not_found`，`detail.path` 指向绝对路径。
- 与「空数组」区分：空数组是 warning `no_calendar_files`，退出 0，按全空闲计算。

## 6. 空日历数组

`calendar_files: []`：

- 退出 0，findings 为 `no_calendar_files` + `task_unestimated`；容量等于工作时间。

## 7. 并发锁

输出目录已有 `.lock`：

- 直接跑 plan：退出 2，`plan_locked`，提示锁路径和「确认没有在运行就删除」。
- 把 mtime 改到 20 分钟前再跑：退出 0，warning `stale_lock_removed`，计划正常写入。

## 8. `--no-report`

- plan 退出 0；`files.reportHtml` 为 `null`；`report.html` 不存在；其余三文件存在。

## 9. 没有 plan 的 `today`

- 删除 `.weeklint/plan.json` 后运行：退出 0，`planFound=false`，`blocks` 来自内存计划，不写文件，并提示这一点。

## 10. `explain` 歧义与已完成

- 两个任务标题都含「论文」：退出 2，`ambiguous_task`，`detail.matches` 含 id、title、line。
- 已完成任务：退出 0，`blocks=[]`，`unscheduled=null`，`reason` 为「任务已完成，不参与本周排程。」

## 11. 坏 YAML

`version: [`：

- 退出 2，`config_invalid_yaml`，`detail.line=2`（文件第 1 行内容 + 文件尾换行导致的解析位置），不打印文件全文。

## 12. 不可读日历

`chmod 000 calendar.ics`：

- 退出 2，`calendar_file_unreadable`，`detail.path` 正确，错误含 `Permission denied`，不含文件内容。

## 13. 纯日期 `--now`

`--now 2026-11-02`：

- 退出 0；`now=2026-11-02T00:00:00-05:00`；与带时间的行为一致。

## 14. DST

- 春令时不存在时间 `@due(2026-03-08T02:30)`：顺延到 03:30，warning `dst_adjusted`，退出 0。
- 秋令时歧义时间 `@due(2026-11-01T01:30)`：取第一次（-04:00），warning `dst_adjusted`。
- 带显式偏移 `-05:00` 的同一墙钟不 warning。

## 15. 到期但未排程

`max_tasks_per_day=1`，只给周一 3 小时，三个今天到期的任务：

- plan 退出 1；两个任务 `task_unscheduled`。
- today 的 `dueTodayUnscheduled` 返回这两个任务，含 title/taskId/due。

## 16. 环境变量

- `WEEKLINT_NO_COLOR=yes`、`WEEKLINT_DEBUG=2`、`WEEKLINT_NOW=nope` 都是退出 2、`invalid_env`。
- `WEEKLINT_CONFIG` 与 `WEEKLINT_NOW` 同时设置且命令行不带参数时，check 使用它们并得到 2026-W45。

## 发现并修掉的问题

1. **回滚后的未排分钟数错误**：`plan.unscheduled` 原来用「剩余 - 本次已放」，但本次块已回滚，导致 `summary.unscheduledMinutes` 少算。改为整条剩余分钟，并加 `test_rollback_has_no_half_task` 断言 180 分钟。
2. **DST 规格未落地**：`dst_adjusted` 之前只写在 SPEC 里，代码没有产生。补 `Task.dst_adjusted`、`parse_due` 的顺延/歧义检测和 budget finding，加两个 DST 测试。
3. **`init` 生成配置与 SPEC 示例格式不一致**：`yaml.safe_dump` 把行内数组拆成多行。改为固定模板，保持最小配置可读；同时恢复 SPEC 要求的一行成功提示。
4. **环境变量非法值未校验**：`WEEKLINT_NO_COLOR=yes` 之前被静默忽略；现在 `invalid_env`，且 `WEEKLINT_NOW` 在读取配置前就校验格式。
5. **`--week 2026-W1` 被接受**：改为严格 `YYYY-Www`，未补零退出 2。
6. **旧计划重叠块未拦截**：`_locked_blocks` 增加块与已保留块的重叠检查，避免损坏的 plan.json 造成双占。

## 没有复现/不修

- Windows 实机不可用；只通过 CI 配置覆盖，README 明确写「本地未实机验证」。
- `RECURRENCE-ID` 合并是已知限制，按 v0.1 范围跳过并 warning。
- 日历厂商导出格式无法穷举；只按 RFC 5545 和 `icalendar` 行为测试。
